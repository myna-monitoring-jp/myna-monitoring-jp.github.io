# 新規性の判定（novelty）— 台帳に載せる基準

2026-09-09 追加。`src/pipeline/novelty.mjs`。

## なぜ必要になったか

2026-09-08 の日別レポートは22件すべてが「既知の更新」で、当日の新規報道が
1件も入っていなかった。内訳は次のとおり。

| 区分 | 件数 |
| --- | --- |
| 政府広報の常設解説ページ（2024年7月〜2026年3月掲載） | 11 |
| デジタル庁の常設ページ・ダッシュボード | 4 |
| 前日から引き継いだ報道 | 6 |
| アプリストア評価 | 1 |

一方、当日は次の新規報道を実際に収集していたが、台帳に1件も入らなかった。

- 「マイナアプリ」提供開始（6媒体）
- 救急隊がマイナ保険証を活用する「マイナ救急」が全国で本格スタート
- 大雨被災者、マイナ保険証なしで受診可
- マイナンバーカードで避難所の受け付け、デジタル化の実証実験（秋田県総合防災訓練）
- 医療費助成オン資、約半数の薬局で導入
- 郵便局や県警を名乗る不審電話、マイナンバーカード画像を要求

原因は4つ重なっていた。

1. **種別で捨てていた。** `eventClass` が `other` のクラスタを台帳から除外していた。
   報道候補は news.google.com が robots.txt で全面拒否のため本文が取れず、
   判定材料は見出し1行だけ。本文向けの語彙しか無かったため、
   収集した報道136件のうち105件が `other` になった。
2. **掲載日で絞っていなかった。** 政府広報の一覧ページは掲載年月に関わらず
   全件を返すため、常設の解説ページが毎日並んだ。
3. **差分判定が全件「訂正」になっていた。** 影響人数は台帳に書かれておらず、
   JSON往復で `undefined` として読み戻される。当日算定値の `null` と比較して
   「変更された」と判定し、`before.affectedCount !== null`（`undefined` は真）で
   訂正条件を通していた。
4. **クエリが事案語を必須にしていた。** 広域発見10本のうち9本が
   `(障害 OR 不具合 OR エラー …)` を含み、事案語を持たない新規の発表は
   `"マイナ保険証" 最新` の1本しか通り道が無かった。

## 判定の順序

```
1. 日単位の日付が取れる（updatedAt / publishedAt / occurredAt / 表題の和暦）
     → 窓内（既定7日）なら fresh、窓外なら stale
2. 年月しか取れない（政府広報のURLは /article/202508/ 形式）
     → 当月・前月なら fresh、それ以前なら stale
3. どちらも取れない
     → source_registry.yml で daily_observation: true なら observed
     → それ以外は standing
```

`fresh` と `observed` だけを台帳に載せる。`pinned` は判定を免除する。

## 種別が決まらない新規はどうするか

**捨てない。** `eventClass: 'uncategorized'` を立て、必ずレビュー待ちに入れる。
種別を機械が決められないことは、その動きが無いことの根拠にならない。
レポート上は「その他の新規の動き」欄に出る。

## 前日の台帳にあることは免除理由にしない

一度免除すると常設ページが「既知」として毎日残り続ける。
追い続けるべき事象は当日の続報が付けば `publishedAt` が窓内に入るので落ちない。
続報が7日付かないものは沈静化させる——7日ルールそのもの（仕様§10）。

## 落としたものの記録

`data/runs/<日付>/screened.jsonl` に `verdict` と `reason` 付きで残す。
「選定で落ちた」のか「収集できていない」のかを後から切り分けるため（仕様§18）。
