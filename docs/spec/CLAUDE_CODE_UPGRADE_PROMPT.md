# Claude Codeへの改修依頼

現行の `myna-monitoring-jp.github.io` リポジトリを読み込み、日次リサーチの品質を改善してください。

必ず次のファイルを先に読んでください。

1. `RESEARCH_PIPELINE_SPEC.md`
2. `query_catalog.yml`
3. `source_registry.yml`
4. `event_schema.json`

## 目的

現在のWebサイトのUIを活かしつつ、日次更新の中身を次の品質へ引き上げます。

- 検索結果の単純要約ではなく、複数パスの調査
- 一次情報優先
- 記事単位ではなく事象単位
- 前日との差分
- 発生日・公表日・更新日の分離
- 公式、報道、SNSの分離
- 既存批判と新規広報起点反応の分離
- マイナ関連のシステム層の分離
- 不明値を推測しない
- 全リンクをカード内から別タブで開ける

## 最初に行う監査

実装前に現行リポジトリを調査し、`docs/current-state-audit.md` を作成してください。

最低限、次を確認してください。

- 使用フレームワーク
- GitHub Pagesのデプロイ方式
- 現在の検索API・RSS・スクレイピング
- 検索クエリの生成方式
- 前日状態の保存有無
- 事象クラスタリングの有無
- 一次情報の追跡有無
- SNS取得方法
- リンク検証
- 日次スケジュール
- Secretsと環境変数
- 現行データモデル
- 現行テスト

監査後、仕様との差分を一覧化してください。

## 実装の分割

一度に巨大なLLMプロンプトで完結させず、次のジョブまたはモジュールへ分離してください。

1. `discover`：広域検索、公式新着、RSS、監視URL
2. `fetch`：ページ本文・メタデータ取得
3. `extract`：構造化事実の抽出
4. `cluster`：同一事象の統合、転載除去
5. `verify`：一次情報探索、数値・日付・復旧確認
6. `reaction`：SNS・コメント・App Store反応
7. `diff`：前日差分、状態遷移、7日ルール
8. `score`：影響度と話題度を別計算
9. `compose`：JSONレポート生成
10. `render`：Web画面・日別HTML生成
11. `qa`：リンク、日付、数値、表現、必須ソース検証
12. `publish`：GitHub Pagesへ反映

## データモデル

`event_schema.json` をTypeScript型とランタイム検証へ変換してください。

最低限：

- `ResearchRun`
- `QueryLog`
- `Event`
- `Source`
- `PublicVoice`
- `Survey`
- `FactCheck`
- `Metric`
- `Report`

JSON SchemaをCIで検証してください。

## 検索処理

`query_catalog.yml` を読み込み、以下を実行してください。

- 直近24時間の主検索
- 72時間の取りこぼし回収
- 前日要注視・続報待ちのクローズ検索
- 自治体・保険者の公式サイト検索
- 医療機関・周辺IT・サイバー検索
- 行政広報・広告・炎上検索
- 重要上位案件のみSNS・コメント深掘り

同じクエリを無限反復しないよう、検索停止条件を実装してください。

## 検索ログ

全クエリについて以下をJSONLで保存してください。

- 実行時刻
- クエリ
- 目的
- プロバイダー
- 結果件数
- 採用URL
- 新規重要事象数

## 一次情報優先

重要度60点以上の案件は原則として一次情報必須です。

一次情報が見つからない場合：

- `primarySourceConfirmed=false`
- `reviewStatus=review_required`
- HTMLに「一次情報未確認、報道ベース」と表示

## クラスタリング

同一事件の記事を1つの事象へ統合してください。

- Yahoo!転載
- FNN系列の同一原稿
- 通信社配信の転載
- PR TIMES転載

は独立媒体数へ重複計上しないでください。

保存値：

- `rawArticleCount`
- `independentMediaCount`
- `majorMediaCount`
- `syndicatedCount`

## システム層の分離

最低限、以下を別レイヤーとして持ってください。

- オンライン資格確認本体
- マイナ保険証利用登録
- 医療保険情報取得API
- PMH情報連携API
- マイナポータル自己情報取得API
- マイナアプリ
- JPKI
- 電子証明書更新窓口
- パスポートオンライン申請

1つの障害から「マイナ保険証全体が停止」と推論しないでください。

## 世論・反応

- 代表性のある世論調査とSNSを別モデル・別UIにする
- SNSは全国世論として表示しない
- 反応数に取得時点を保存
- 見つからない声を生成しない
- 反応がなければ「新規の有意な反応は確認できず」
- 予測は「広報上のリスク」へ
- 広報公開前後を分ける

## 炎上判定

単に批判が存在するだけで炎上扱いしないでください。

判定材料：

- 公式投稿の反応急増
- 否定的二次投稿
- 主要媒体・Yahoo!ニュース記事化
- 著名人・議員・団体への波及
- 公式の訂正、削除、謝罪、中止

広報案件は次に分類してください。

- `reported_backlash`
- `active_watch`
- `active_stable.quiet`
- `active_stable.positive`

公金受取口座のような案件では、制度への既存批判と広告公開後の反応を別イベントとして保存してください。

## 重要度

`impactScore` と `attentionScore` を分けてください。

- 影響が重大でも話題が小さい事故
- 話題は大きいが実害が限定的な広報炎上

を同じスコアにしないでください。

## 状態

- 新着
- 要注視
- 続報待ち
- 計画停止
- 改善中
- 解消済
- 沈静化
- アーカイブ

`lastMaterialUpdateAt` から7日間重要更新がなければダッシュボードから外し、詳細・アーカイブには残してください。`pinned=true` は例外です。

## HTML・リンク

各カードに必ず次の4ブロックを表示してください。

A. ニュース自体
B. 国民の声・現場の声
C. 事実関係・補足
D. 出典・リンク

外部リンクは必ず：

```html
<a href="https://..." target="_blank" rel="noopener noreferrer">一次情報を開く</a>
```

禁止：

- 空href
- `javascript:void(0)`
- `#`だけのリンク
- 透明オーバーレイ
- カード全体を覆うリンク
- ステータスラベルをボタン風にすること

E2Eテストで全外部リンクの `href`, `target`, `rel` を検証してください。

## QA

公開を止める条件：

- 重要度大なのに一次情報も「一次情報未確認」表示もない
- 日付と曜日が不一致
- 未来日付
- 数値の対象範囲が不明
- SNSを全国世論と表現
- 既存批判を新規広報炎上として計上
- 計画停止を障害と表現
- 登録率を利用率と表現
- 外部リンクが空または押せない
- JSON Schema違反

## 段階導入

Phase 1：現行UIを維持し、データモデル・検索ログ・差分・リンクQAを導入

Phase 2：5パス検索、一次情報探索、事象クラスタリング、スコアリングを導入

Phase 3：SNS反応、炎上判定、レビュー画面、Teams通知を導入

Phase 4：検索品質の評価セットを作り、過去30日分で再現率・誤判定を改善
